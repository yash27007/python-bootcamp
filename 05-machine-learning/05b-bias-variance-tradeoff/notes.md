# 05b – Bias-Variance Tradeoff

## Problem

You fit two models on the same training data. Model A gets training error almost zero. Model B gets a noticeably higher training error. You deploy both and measure error on new, unseen data — and Model B wins. This happens constantly in practice, and it's not a fluke: **why can a model that fits the training data worse generalize better than one that fits it almost perfectly?** Answering this precisely — not just "overfitting," as a label, but as a decomposable, measurable quantity — is what this topic is for.

## Intuition

Imagine you're trying to hit a bullseye on a dartboard, but you only get to see where darts landed on *previous* throws (your training data) before making your prediction for a new throw.

- **High bias:** you consistently throw darts that cluster tightly together, but centered well away from the bullseye — e.g. always 6 inches to the left. Every throw is wrong in the *same* systematic way. Averaging your throws doesn't help — the average is still 6 inches off.
- **High variance:** your throws scatter wildly around the board — sometimes far left, sometimes far right, sometimes above, sometimes below — but if you average infinitely many of them, the average would land on the bullseye. Any *single* throw, though, is unreliable.
- **What you actually want:** throws that are both centered on the bullseye (low bias) and tightly clustered (low variance).

Translate to models: **bias** is how wrong a model is *on average*, across many different training sets it could have been fit on — a systematic error baked into the model's assumptions (e.g. a straight line can never curve to match a truly curved relationship, no matter which data it's trained on). **Variance** is how much the model's predictions *change* depending on which particular training set it happened to see — a highly flexible model can wiggle to match noise in whatever data it's given, so a different training sample produces a noticeably different fitted model.

A concrete numeric version: suppose the true relationship is $y = \sin(x) + \varepsilon$ with small noise $\varepsilon$. Fit a degree-1 (straight-line) model — it will consistently miss the curvature of $\sin(x)$ the same way no matter which noisy sample you give it (high bias, low variance). Fit a degree-15 polynomial — it will snake through every noisy wiggle in whatever specific sample it sees, producing wildly different curves from one sample to the next (low bias in principle, but high variance in practice, because it also fits the noise).

## Why simpler approaches fail

The naive strategy is: **"just minimize training error."** Give the model as much flexibility as possible and let it fit the training data as closely as it can. This fails silently, because training error and test error diverge:

- A sufficiently flexible model (high-degree polynomial, deep unpruned tree, huge neural net with too little data) can drive training error arbitrarily close to zero by fitting the *noise* in the training sample, not just the underlying signal.
- Noise, by definition, does not repeat in a new sample — it's a different random draw. A model that memorized the training noise has learned something that actively hurts it on new data.
- So "minimize training error" as a sole objective has no mechanism to distinguish "fitting the true pattern" from "fitting this specific sample's random noise," and will happily do the latter if given enough flexibility. This is overfitting, and it is invisible if you only ever look at training error — it only shows up as a training/test gap.

What's missing from "minimize training error" is any accounting for the fact that a model's error on new data has more than one source, and one of those sources (variance) actively gets *worse* as the model is given more freedom to fit training data closely. You need a framework that separates "the model is wrong because it's too rigid" from "the model is wrong because it's too sensitive to which sample it saw" — that's the bias-variance decomposition.

## Mathematical foundation

### Setup

Assume the data is generated by a true function $f$ plus irreducible noise:
$$y = f(x) + \varepsilon, \qquad \mathbb{E}[\varepsilon] = 0, \quad \text{Var}(\varepsilon) = \sigma^2$$
$\varepsilon$ is noise inherent to the process — measurement error, unmodeled randomness — that no model, however good, can predict away.

We fit a model $\hat{f}$ on a training set $D$ drawn randomly from the data distribution. Because $D$ is random, $\hat{f}$ is a random function — a different draw of $D$ produces a different fitted $\hat{f}$. We want the **expected squared error** at a fixed test point $x$, averaged over the randomness in both the training set $D$ and the noise in a fresh test label $y$ at $x$:
$$\mathbb{E}_{D,\varepsilon}\left[(y - \hat{f}(x))^2\right]$$

### Derivation

Write $y = f(x) + \varepsilon$, and let $\bar{f}(x) = \mathbb{E}_D[\hat{f}(x)]$ denote the average prediction at $x$ over all possible training sets — i.e. what you'd get if you could fit on infinitely many different samples and average the resulting predictions.

Expand the squared error:
$$\mathbb{E}\left[(y - \hat{f}(x))^2\right] = \mathbb{E}\left[(f(x) + \varepsilon - \hat{f}(x))^2\right]$$

Add and subtract $\bar{f}(x)$ inside the square:
$$= \mathbb{E}\left[\big((f(x) - \bar{f}(x)) + (\bar{f}(x) - \hat{f}(x)) + \varepsilon\big)^2\right]$$

These three terms are: a constant ($f(x) - \bar{f}(x)$, no randomness — $f$ is the true function, $\bar f(x)$ is a fixed expectation), a zero-mean random term over $D$ ($\bar{f}(x) - \hat{f}(x)$, since $\mathbb{E}_D[\hat f(x)] = \bar f(x)$ by definition), and a zero-mean random term over the noise ($\varepsilon$), independent of $D$. Because the cross terms between a zero-mean random variable and anything independent of it vanish in expectation, the square expands cleanly into three separate expectations:
$$= \underbrace{\left(f(x) - \bar{f}(x)\right)^2}_{\text{Bias}^2} + \underbrace{\mathbb{E}_D\left[(\hat{f}(x) - \bar{f}(x))^2\right]}_{\text{Variance}} + \underbrace{\mathbb{E}[\varepsilon^2]}_{\sigma^2}$$

So:
$$\mathbb{E}\left[(y - \hat{f}(x))^2\right] = \text{Bias}(\hat f(x))^2 + \text{Variance}(\hat f(x)) + \sigma^2$$

### What each term means

- **Bias$(x) = f(x) - \bar f(x)$**: the gap between the true function and the *average* prediction the model family would make if you could fit it on unlimited different training sets. This is a property of the model family's flexibility relative to the true function's shape — a straight line has nonzero bias against a truly curved $f$ no matter how much data you feed it, because averaging infinitely many straight-line fits still gives you a straight line.
- **Variance$(x) = \mathbb{E}_D[(\hat f(x) - \bar f(x))^2]$**: how much the prediction at $x$ *fluctuates* depending on which specific training set was drawn. This is a property of how sensitive the fitting procedure is to the particular sample of noise it happened to see.
- **$\sigma^2$**: the irreducible noise variance. No model, however perfectly matched to $f$, can predict $\varepsilon$ — this term is a floor on achievable error that exists independent of model choice.

### Why there's a tradeoff

Increasing model flexibility (higher polynomial degree, deeper tree, more parameters) generally **decreases bias** (the average fit over many samples can track the true $f(x)$ more closely) but **increases variance** (each individual fit becomes more sensitive to the particular noise realization in its training set, since a flexible model has room to chase noise as well as signal). Decreasing flexibility does the reverse. Because total expected error is the *sum* of both, minimizing training error alone (which pushes toward more flexibility, hence lower bias) ignores the variance term entirely — and past some point, variance grows faster than bias shrinks, so total test error goes *up* even as training error keeps going down. That crossover is the U-shape you'll see in the experiment below.

## Algorithm

To empirically estimate bias², variance, and test error at a fixed model complexity, without knowing $f$ or $\sigma^2$ analytically:

1. Fix a true function $f$ and noise level $\sigma$; fix a grid of test points $x_1, \dots, x_m$ where you'll measure bias/variance.
2. For $r = 1, \dots, R$ repetitions:
   a. Draw a fresh noisy training set $D_r$ of size $n$ from $f + \varepsilon$.
   b. Fit the model of the chosen complexity on $D_r$, producing $\hat f_r$.
   c. Record $\hat f_r(x_j)$ for every test point $x_j$.
3. At each test point $x_j$: compute $\bar f(x_j) \approx \frac{1}{R}\sum_r \hat f_r(x_j)$ (empirical mean prediction across repetitions).
4. Empirical Bias$^2(x_j) \approx (f(x_j) - \bar f(x_j))^2$.
5. Empirical Variance$(x_j) \approx \frac{1}{R}\sum_r (\hat f_r(x_j) - \bar f(x_j))^2$.
6. Average Bias$^2$ and Variance over all test points $x_j$ to get single summary numbers per model complexity.
7. Repeat steps 2–6 for each model complexity of interest (e.g. polynomial degree 1 through 15), and plot Bias$^2$, Variance, and their sum (+ $\sigma^2$, or measured test MSE) against complexity.

## Practical implementation

You cannot directly measure bias/variance on real-world data, because you don't know the true function $f$ or get to redraw many independent training sets from the real generating process — you have exactly one dataset. In practice, two tools substitute for the "resample and measure" experiment above:

- **`05-cross-validation`** approximates the *variance* signal indirectly: the spread of scores across folds tells you how sensitive the model's performance is to which subset of data it was trained/evaluated on — the same underlying idea as this topic's "refit on many resampled training sets," just applied to one real dataset instead of a known synthetic $f$.
- **`04-regularization`** (upcoming topic) is the primary *lever* for managing this tradeoff directly: it constrains model flexibility (e.g. penalizing large coefficients) to deliberately trade some bias for a reduction in variance, moving a model back down the right side of the U-shaped curve without literally reducing its parameter count.

Together: cross-validation *measures* where you are on the tradeoff (via test-score variance and train/test gap), regularization is a *knob* you turn in response to what you measure.

## Experiment

**Hypothesis (stated before running):** as polynomial degree increases from 1 to 15, (1) training error should decrease monotonically (more flexible models fit their own training sample better, always); (2) empirical bias² should decrease with degree (higher-degree polynomials can, on average, track the true sine curve more closely); (3) empirical variance should increase with degree (higher-degree fits become increasingly sensitive to the specific noisy sample they were trained on); and (4) test error (bias² + variance, and separately measured average test MSE) should be U-shaped — high at low degree (underfitting, dominated by bias), high again at high degree (overfitting, dominated by variance), with a minimum somewhere in between.

**Setup:** true function $f(x) = \sin(2\pi x)$ on $x \in [0, 1]$, Gaussian noise $\sigma = 0.3$, training set size $n=25$ resampled `R=200` times per degree, polynomial degrees 1–15 fit via `np.polyfit`, evaluated on a fixed held-out test grid.

**Actual result:** recorded and plotted directly in `bias-variance-tradeoff.ipynb` — see its final markdown cell for the concrete numeric read of where the minimum test-error degree falls and how sharply variance grows past that point for this noise level and sample size. Train error is confirmed monotonically decreasing across the executed run.

**Interpretation:** the U-shape (when it appears in the actual run) is direct empirical confirmation that "minimize training error" is not equivalent to "minimize test error" — the two curves diverge as degree increases, with the divergence entirely attributable to the variance term growing.

**Limitations:** results depend on the chosen noise level ($\sigma=0.3$) and sample size ($n=25$) — a larger $n$ shifts the variance curve down and the optimal degree up (see Failure modes below); the notebook uses a single true function shape (`sin`) and unregularized polynomial fits via `np.polyfit`, which is one specific (and somewhat extreme/illustrative) way to vary model complexity — real models vary complexity in less discretely-steppable ways (tree depth, regularization strength, network width) and won't reproduce an identically shaped curve, though the qualitative U-shape generalizes.

## Failure modes

- **High-variance regime (overfitting):** training error near zero, test error much higher, and predictions fluctuate a lot between differently-sampled training sets. Symptom: large train/test gap. Fix: reduce model flexibility, add regularization, add more training data (more data specifically shrinks variance, because each individual fit is less dominated by any single noisy sample).
- **High-bias regime (underfitting):** training error and test error are both high and close to each other. Symptom: no meaningful train/test gap, but both errors are bad. Fix: increase model flexibility, add more/better features — but *not* more data, since more data does nothing to reduce a systematic bias caused by the model family being too rigid to represent $f$.
- **"More data helps" is regime-dependent.** More data reduces variance (each fit becomes less sensitive to any one sample's noise) but does not reduce bias (a straight line stays a straight line's worth of wrong no matter how many points you fit it on). If a model is underfitting, collecting more data is close to wasted effort; the fix is a more flexible model or better features.
- **"Just add more parameters" is not free.** Additional flexibility only helps while bias is still the dominant error term; past the point where bias is already low, additional flexibility purely adds variance, making test error worse even as training error keeps dropping — the central lesson this topic exists to make precise.

## Real-world usage

- **Model selection** (choosing polynomial degree, tree depth, k in kNN, regularization strength, network architecture size) is, in every case, a bias-variance tradeoff decision, usually made by watching a validation curve for the U-shape and picking the complexity near its minimum.
- **"Why is my model bad?" debugging** in practice starts by checking whether you're in the high-bias or high-variance regime (train/test gap size), because the fix is opposite in each case — this framework is the fastest correct diagnostic available before reaching for more complex remedies.
- **Ensemble methods** are explicitly designed around this tradeoff: bagging (e.g. random forests) reduces variance by averaging many high-variance, low-bias models; boosting reduces bias by sequentially combining many high-bias, low-variance (weak) models. Both strategies only make sense once you understand which term they're attacking.

## Mental model

Bias is being wrong on average; variance is being unstable across different training sets — you cannot always reduce both at once, so every model-complexity decision is really a decision about which one to pay for.
